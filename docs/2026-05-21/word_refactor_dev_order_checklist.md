# 背单词重构开发顺序清单（2026-05-21）

> 面向当前项目实际状态整理的执行顺序清单。目标不是重新规划全部方案，而是按“先修闭环、再补展示、最后扩长期复习”的顺序推进，减少并行改动带来的回归风险。

## 一、开发总原则

- 先修当前主闭环中的确定性 bug，再补外围展示能力
- 先收口已有状态流转，再引入新的长期复习字段和流程
- 每一步都要求至少具备手测路径，避免“代码落了一半但无法确认是否可用”
- 所有开发顺序都以“不破坏当前阶段 1/2/3 已完成能力”为前提

## 三、第 1 步：修复复习进度保存问题

**目标**

- 让复习过程中和复习完成后的状态，能够稳定写入数据库并在学习中心正确反映。

**已完成结论**

- [x] 已梳理复习完成相关写库入口，并确认此前存在多处异步收口导致的竞态
- [x] 已将复习答对后的单词状态更新收敛为统一仓库主链
- [x] 已将轮次完成判定收敛为待复习池清空时统一收口
- [x] 已确保学习中心继续通过 `getPendingReviewEntry()` 读取最新入口状态
- [x] 已修复“最后一题完成但待复习入口残留”的主要触发路径

**完成标准**

- [x] 复习答对后，单词状态能稳定更新
- [x] 复习整轮完成后，待复习入口能正确消失
- [x] 重进页面后不会重复看到已经完成的旧复习轮

## 四、第 2 步：修复学习完成后下一批词续接问题

**目标**

- 让一轮学习完整结束后，下一轮能从正确的词书游标继续，而不是卡在旧位置或续接错误。

**已完成结论**

- [x] 已复核学习轮完成时词书游标推进逻辑
- [x] 已确认 `markStudyRoundReviewPending()` 在完成态前先推进游标
- [x] 已为读取学习会话补充“空活动轮次”兜底处理
- [x] 已确保“立即复习”和“稍后再说”两条路径都不会阻塞下一轮起点

**完成标准**

- [x] 完成一轮学习并退出后，再次开始学习能进入下一批词
- [x] 不会重复从已完成的那一批词重新开始
- [x] 待复习状态存在时，也不会污染下一轮学习的起点
