# Seedie 真实试用与学习体验改进计划

日期：2026-11-06。状态：第一阶段已进入实施与验收，后续阶段仍为建议稿。实施记录见 [changelog.md](./changelog.md)。

第一阶段执行拆解见 [phase1_execution_plan.md](./phase1_execution_plan.md)。该文档进一步明确了任务计数、代币同步与本地露珠的区别，以及恢复改造对工期的影响；第一阶段验收以该细化口径为准。

## 1. 目标与判断依据

用户选择的优先方向：真实试用与学习体验。

本轮目标：让学生知道今天学什么，顺利完成并理解一次学习，在下一次打开时能继续；让教师能发现需要帮助的学生并完成反馈。

依据来自仓库源码静态阅读，尚未进行设备实测、用户访谈或线上数据分析。以下明确区分已观察到的实现与待验证的产品假设；不能据此声称已有真实用户流失。

建议先选一个机构、一个年级、一个教材版本，招募 10–20 名学生和 1–2 名教师进行两周试用。数量与时间是建议的试点范围，不是已确定的资源。

核心指标：每周至少完成两次有效学习的试用学生比例。有效学习指完成指定学习目标或有效作业提交；打开页面、播放视频、重复领取奖励不计入。辅助观察延迟复习表现与教师反馈闭环，避免只优化完成次数。

## 2. 已观察到的问题与机会

| 证据 | 产品影响或待验证假设 | 优先级 |
|---|---|---|
| `DashboardViewModel` 默认词汇任务为“学习单词 20 个”；主界面 `MainViewModel.handleCompletedTasks` 按模块和 `isCompleted` 完成任务，没有核对 20 词 | 展示目标与结算条件不一致，影响信任 | P0 |
| `DailyMissionSection.TaskCard` 没有任务跳转，勾选按钮禁用 | 学生看到任务后仍需自行寻找入口 | P0 |
| 默认任务固定包含词汇、听力、阅读、写作 | 未必符合当天作业、内容可用性和学生时间；需访谈验证 | P1 |
| `SeedieNavHost` 多个练习参数与待处理结果放在 `remember` 中 | 存在重建后丢失上下文的风险；具体恢复表现需实测 | P0 验证 |
| 学习结果通过导航返回再由主界面异步处理；会话去重集合在内存中 | 结算中断与重放场景需要端到端验证；不等于已证实重复发奖 | P0 验证 |
| 森林规则含 60 秒退出宽限与清除枯树花费 50 代币 | 临时中断可能产生挫败感；需区分中断原因 | P1 |
| 教师首页以学生列表和详情入口为主 | 教师发现未完成、待批改、反复出错学生的效率可能不足 | P1 |
| 词汇测评历史已有实测、插值与延续的来源区分 | 保留已有区分，验证学生是否理解“估算”与“掌握”的差异 | P1 |
| 已有业务单元测试，但旧总览仍称测试为占位等 | 开发与验收口径应更新，避免按旧文档判断功能状态 | 支撑工作 |

## 3. P0：试用前必须完成

### A. 建立一条可执行的今日学习路径

- 首页增加一个主要行动按钮，按“继续未完成 → 临近截止作业 → 待复习 → 今日新学”的默认顺序推荐；允许学生切换，不强制顺序。
- 展示任务名称、内容范围、当前进度、预计用时和完成条件。预计用时先按内容配置，不能伪装成精确预测。
- 每日任务可以直接进入对应内容；没有可做作业时不生成“提交作文”等无法完成的任务。
- 首次使用只完成年级/教材确认、词书准备和首个短任务；词汇测评可稍后进行。
- 没有老师绑定或内容未配置时，给出明确原因、可用的自由练习与解决路径。

验收：5 名首次使用的目标学生中，至少 4 名在不接受口头引导的情况下，于进入首页后 60 秒内开始适合自己的任务。该门槛是试用验收目标，不是行业基准。

### B. 统一目标、进度、奖励口径

- 词汇任务二选一：短期改为“完成一次单词学习”，或真正累计当日符合定义的 20 个不同单词；先确定定义再实现。
- 建议本轮采用真实计数：新词完成学习阶段计入新学，同一词重复作答不重复计数；复习单列，不混入“新学 20 词”。
- 页面显示 `12/20` 等实际进度；任务达标与一次会话结束分开处理。
- 结算区分“学习完成”“奖励待同步”“奖励到账”，显示本次新增和待同步状态，避免失败时提示成功。
- 核对每日任务跨午夜、切换账号、重进页面和重复提交；重试不得重复推进或重复发奖。

验收：未达标不完成任务；达标只完成一次；结算页、任务卡和余额使用一致的数据口径。

### C. 明确中断、恢复与提交规则

- 逐模块制定恢复契约：词汇/阅读/听力恢复到最近已确认答题；作文草稿与已上传附件保留；服务端已提交结果可重新查询。
- 暂停、返回、切后台、进程被系统回收、断网、上传失败分别验收。登录过期后重新登录可回到待完成事项。
- 重要提交使用稳定的会话/提交标识；把学习完成与奖励结算状态持久化，恢复时可补结算。
- 对需联网的内容明确提示；已有下载内容可继续，不承诺全功能离线。
- 试用阶段，技术故障与正常暂停不触发枯树或扣费；主动结束未完成学习前告知后果。

验收：按场景矩阵实测后，无已确认答案丢失、无重复扣款/发奖、无技术故障导致的惩罚；已提交作业可在教师端查到。恢复粒度和离线范围在试用说明中明确。

### D. 准备一套可信内容与最小诊断能力

- 首轮只开放选定年级/教材的已检查内容；抽查题目答案、解析、例句、译文、音频与题目对应关系。
- 听力完成播放失败/重试/暂停恢复检查；图片、作文上传和视频在目标平板与试用网络上实测。
- 未完成模块弱化或隐藏；空目录解释原因并提供返回或替代任务。
- 提供“反馈此题”入口，关联内容 ID、版本与问题类型，默认不收集多余个人信息。
- 记录任务曝光、开始、恢复、完成、提交、失败、结算成功/失败等最小事件；区分新学、复习、自由练习和作业，重试去重。

验收：试用内容无已知答案错误或关键媒体失效；能追踪一次学习为何中断或提交失败。事件不能仅凭页面退出就认定学生主动放弃。

## 4. P1：试用期间增强学习价值

### A. 学完后给出具体反馈

- 统一结算结构：完成内容、正确率、仍需复习的知识、奖励状态、一个主要下一步。
- 阅读错题定位原文证据，听力错题跳到对应片段；先检查现有回顾能力，只补缺口。
- 词汇错词进入后续复习；已有轮次复习保留，新增跨天到期复习前先明确状态与去重规则。
- 不把即时答对直接表述为长期掌握；在第 2/7 天用少量同知识点题观察保持情况，不承诺学习效果提升。

验收：学生能解释至少一道错题原因，并找到下次复习入口；延迟复习按同类内容观察，不将不同难度测评值直接相减解释为成长。

### B. 教师看见需要采取的行动

- 首页增加未开始/未提交、待批改和已返还未查看三类待办；先复用已有作业状态。
- 作业详情支持按状态筛选，查看高错误率题目及名单；小样本明确显示人数。
- 学生收到批改后有可见入口，读完能回到原题或订正；先明确“查看”和“完成订正”各自含义。
- 建立一页简短周回顾：做了什么、卡在哪里、下一周安排什么。优先帮助教师行动，不堆指标。

验收：教师能在 2 分钟内找到未提交学生和待批改作业；一次作文从布置到学生查看反馈的全链路可追踪。

### C. 减轻游戏化对学习的干扰

- 学习入口优先；树种选择允许记住上次选择，减少每次开始前的操作。
- 试用先保留正向奖励，暂停枯树清理收费；将“未完成”呈现为可继续的任务。
- 解释代币、露珠的来源与用途；只有确实可消费的奖励才突出展示。
- 趋势主视图突出真实测评点与时间，插值可收起；不新增随机波动来制造成长感。

验收：学生能说清今天完成了什么及两种奖励的用途；不因担心惩罚而拒绝退出或反馈问题。通过访谈验证。

## 5. 排期与依赖

以下为小团队粗排，需完成工作量拆分后再承诺交付日期；P0 质量门槛优先于固定周数。

| 阶段 | 参考时长 | 交付物 | 进入下一阶段的条件 |
|---|---|---|---|
| 基线验证 | 2–3 个工作日 | 真实设备完整走查、5 名学生观察、教师访谈、问题清单 | 确认试用对象/教材/设备和主要阻碍 |
| P0 实现 | 约 2 周 | 今日主路径、任务口径、恢复与结算、内容检查、最小事件 | 关键验收场景通过，无阻断性问题 |
| 受控试用 | 2 周 | 10–20 名学生的学习记录与访谈、教师反馈 | 完成率与问题原因可解释 |
| P1 迭代 | 约 1–2 周起 | 反馈/复习、教师待办、简化奖励，按试用结果选做 | 使用与学习价值有证据支持 |

依赖顺序：任务与有效学习定义 → 状态/事件定义 → 今日主路径与结算 → 故障恢复验收 → 试用 → 个性化与教学分析。

## 6. 试用评估与上线门槛

- 首次启动率：开始首个任务人数 / 成功进入首页的首次试用学生人数；另记登录/内容准备失败，不能从总漏斗中排除。
- 学习完成率：完成会话 / 有效开始会话；恢复续做按同一会话归并，故障单列原因。
- 作业闭环：已提交、已返还、学生已查看的独立提交数与耗时。
- 回访：记录第 2/7 天回访，并区分学校安排使用与学生自主使用。
- 学习信号：同知识点延迟复习表现、学生解释错题的能力；小样本只作方向判断。
- 可靠性：提交失败、恢复失败、重复结算、媒体失败；任何丢作业、错扣款或跨账号数据泄露都阻止扩量。
- 不先指定任意留存增长百分比。前一周建立基线，后一周结合观察与访谈判断改进；小样本不能宣称统计显著。

## 7. 暂缓与待确认

本轮暂缓新口语/语法大模块、AI 对话、排行榜、复杂商城玩法、家长端和全面 UI 重做。保留现有架构，以试用链路涉及的最小改动推进；不将全面重构作为产品改进前置条件。

开始实施前需确认：目标年级与教材、学生实际设备/网络、试用教师与账号准备、可投入的开发与内容审核资源。这些影响范围与排期，不影响先修复目标口径和关键故障恢复问题。

首个建议迭代包：任务口径一致 + 任务直达 + 恢复/结算场景走查。先完成可验收的小闭环，再扩大首页改造范围。
